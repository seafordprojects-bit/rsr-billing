# receive-drydock-job Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the drydocking app's Cloud Run service hand a completed, emailed drydocking job to rsr-billing, where it lands as a DRAFT `DC` billing the user reviews and sends himself.

**Architecture:** One new Edge Function, `receive-drydock-job`, verifies a shared secret and calls one new security-definer RPC, `receive_drydock_job(jsonb)`, which in a single transaction records the receipt (idempotent on `dispatch_id`), fills the client, mints a `RSR-DC-MMYYYY-###` code, prices each document from the DC catalogue, and inserts one `drawing_billing` line per document. The app shows a "From drydocking" badge on such groups. Nothing about sending, numbering or statuses changes.

**Tech Stack:** index.html (one IIFE, SQL generated by `sqlText()`), Deno Edge Function (TypeScript, tested under Node with `--experimental-strip-types`), the existing Node test harness, and `@electric-sql/pglite` ^0.5.8 as the project's first dev dependency, for the RPC tests.

## Global Constraints

- Everything is `index.html`; no build step. New JS goes inside the IIFE, new SQL goes inside `sqlText()`.
- `sqlText()` is a JS template literal: **no backtick and no `${` anywhere in the SQL text**, including comments. Every `create` is `if not exists`; every `alter` is `add column if not exists`; a `create` that can fail sits in a guarded `do` block.
- Policies are `to authenticated` only and named `rsr_dwg_*`. New RPCs are revoked from `public` then `anon`, and granted explicitly; this one is granted to `service_role` only.
- Client writes fill blanks and never overwrite. Billings store the client name as text at creation.
- `drawing_no` holds the billing's own reference and is **left null** on received lines. The project number goes in `remarks`.
- Remarks on every line, identical (it is a `GROUP_FIELDS` field): `Drydocking documents emailed <Month D, YYYY>, confirmed by <name>. Project <no>.`
- Rate: the active DC catalogue row named exactly like the document title, else the active DC row named `Drydocking document`, else 0 and the title is recorded as unpriced.
- Anchored edits only, `s.split(a).join(b)` never `String.replace`, LF line endings via `io.open(p,'w',encoding='utf-8',newline='')`, and `node --check` the extracted script after every index.html edit.
- Adding a hook name that does not exist in index.html breaks every suite: add hook entries in the same task as the function they expose.
- Tests: `node test/run.mjs` must stay green. New suites report `N passed, M failed` on their last line like the others.

```sql
-- ---------------------------------------------------------------
-- Drydocking jobs arrive from the drydocking app (its Cloud Run
-- service POSTs to the receive-drydock-job Edge Function after the
-- documents were emailed). One receipt per dispatch: dispatch_id is
-- the idempotency key, so a retry answers with the group it already
-- made instead of billing the client twice. payload is what arrived,
-- unpriced names the titles no DC catalogue row priced (rate 0).
-- Readable by signed-in users, written only by the RPC below.
-- ---------------------------------------------------------------
create table if not exists billing_drydock_receipt (
  dispatch_id  uuid primary key,
  draft_id     uuid not null,
  group_id     text not null,
  payload      jsonb not null,
  unpriced     jsonb not null default '[]'::jsonb,
  received_at  timestamptz not null default now()
);
alter table billing_drydock_receipt enable row level security;
drop policy if exists rsr_dwg_ddreceipt_read on billing_drydock_receipt;
create policy rsr_dwg_ddreceipt_read on billing_drydock_receipt
  for select to authenticated using (true);

-- receive_drydock_job: one transaction turns a received job into a DRAFT
-- DC billing. Order matters: the receipt insert goes first, so a retry
-- that loses the race finds the row and returns created:false with
-- nothing else touched. The client row is filled where blank and never
-- overwritten (the app's own reconcile rule). The tracking code is the
-- same max-scan nextCode() performs on the device, run here against the
-- table -- detected-not-prevented duplicates apply exactly as they do
-- for two devices. drawing_no stays null: it is the billing's own
-- reference column, never the project number, which goes in remarks.
-- Rate: the active DC catalogue row named like the title, else the
-- active DC row named Drydocking document, else 0 and recorded unpriced.
create or replace function public.receive_drydock_job(p jsonb)
returns jsonb
language plpgsql
security definer
set search_path to 'public', 'extensions'
as $BODY$
declare
  v_dispatch  uuid;
  v_draft     uuid;
  v_gid       text;
  v_existing  text;
  v_client    text;
  v_canon     text;
  v_vessel    text;
  v_sent      timestamptz;
  v_date      date;
  v_prefix    text;
  v_max       int;
  v_code      text;
  v_generic   numeric(12,2);
  v_rate      numeric(12,2);
  v_doc       jsonb;
  v_i         int := 0;
  v_title     text;
  v_pages     int;
  v_unpriced  jsonb := '[]'::jsonb;
  v_remarks   text;
  v_cli       uuid;
  v_addr      text;
  v_email     text;
begin
  if jsonb_typeof(p->'documents') is distinct from 'array'
     or jsonb_array_length(p->'documents') = 0 then
    return jsonb_build_object('ok', false, 'reason', 'documents must be a non-empty list');
  end if;
  v_client := btrim(regexp_replace(coalesce(p->>'client', ''), '\s+', ' ', 'g'));
  if v_client = '' then
    return jsonb_build_object('ok', false, 'reason', 'client is required');
  end if;
  v_dispatch := (p->>'dispatch_id')::uuid;
  v_draft    := (p->>'draft_id')::uuid;
  v_gid      := 'dd-' || v_dispatch::text;

  insert into public.billing_drydock_receipt (dispatch_id, draft_id, group_id, payload)
  values (v_dispatch, v_draft, v_gid, p)
  on conflict (dispatch_id) do nothing;
  if not found then
    select group_id into v_existing from public.billing_drydock_receipt where dispatch_id = v_dispatch;
    return jsonb_build_object('ok', true, 'created', false, 'group_id', v_existing);
  end if;

  v_canon := lower(v_client);
  v_addr  := nullif(btrim(coalesce(p->>'client_address', '')), '');
  v_email := nullif(btrim(coalesce(p->>'client_email', '')), '');
  select id into v_cli from public.clients where name_canon = v_canon limit 1;
  if v_cli is null then
    insert into public.clients (name, address, billing_email)
    values (v_client, v_addr, v_email) returning id into v_cli;
  else
    update public.clients
       set address       = coalesce(nullif(address, ''), v_addr),
           billing_email = coalesce(nullif(billing_email, ''), v_email)
     where id = v_cli
       and ((nullif(address, '') is null and v_addr is not null)
         or (nullif(billing_email, '') is null and v_email is not null));
  end if;

  v_vessel := btrim(coalesce(p->>'vessel', ''));
  v_sent   := coalesce((p->>'sent_at')::timestamptz, now());
  v_date   := (v_sent at time zone 'Asia/Manila')::date;
  v_prefix := coalesce(nullif(p->>'code_root', ''), 'RSR') || '-DC-' || to_char(v_date, 'MMYYYY') || '-';
  select coalesce(max(substring(code from length(v_prefix) + 1)::int), 0) into v_max
    from public.drawing_billing
   where code like v_prefix || '%'
     and substring(code from length(v_prefix) + 1) ~ '^[0-9]+$';
  v_code := v_prefix || lpad((v_max + 1)::text, 3, '0');

  v_remarks := 'Drydocking documents emailed ' || to_char(v_date, 'FMMonth FMDD, YYYY')
            || ', confirmed by ' || btrim(coalesce(p->>'confirmed_by', ''))
            || '. Project ' || btrim(coalesce(p->>'project_no', '')) || '.';

  select default_rate into v_generic from public.drawing_catalog
   where doc_type = 'DC' and active and lower(btrim(name)) = 'drydocking document'
     and default_rate is not null
   order by sort_order limit 1;

  for v_doc in select value from jsonb_array_elements(p->'documents') loop
    v_i := v_i + 1;
    v_title := btrim(coalesce(v_doc->>'title', ''));
    v_pages := nullif(v_doc->>'pages', '')::int;
    select default_rate into v_rate from public.drawing_catalog
     where doc_type = 'DC' and active and lower(btrim(name)) = lower(v_title)
       and default_rate is not null
     order by sort_order limit 1;
    if v_rate is null then v_rate := v_generic; end if;
    if v_rate is null then
      v_rate := 0;
      v_unpriced := v_unpriced || to_jsonb(v_title);
    end if;
    insert into public.drawing_billing
      (group_id, line_no, code, doc_type, bill_date, client, vessel, drawing_no,
       drawing_title, qty, rate, status, remarks, pages, billable)
    values
```

```ts
// completed job here AFTER the documents were emailed to the client. It
// becomes a DRAFT DC billing (receive_drydock_job RPC) that the user reviews
// and sends himself.
//
// Deploy (verify_jwt is OFF for this function in supabase/config.toml -- the
// caller is a server holding a shared secret, not a Supabase user):
//   supabase functions deploy receive-drydock-job --no-verify-jwt
//   supabase secrets set DRYDOCK_INGRESS_SECRET=...

const cleanText = (v: unknown, max: number) =>
  String(v ?? "").replace(/[\r\n\t]+/g, " ").replace(/\s+/g, " ").trim().slice(0, max);
// constant-time compare, same intent as the drydocking server's secretOk
function secretOk(a: string, b: string): boolean {
  if (!a || !b || a.length !== b.length) return false;
  let d = 0;
  for (let i = 0; i < a.length; i++) d |= a.charCodeAt(i) ^ b.charCodeAt(i);
  return d === 0;
}
type Doc = { title: string; pages: number | null };
export type Job = {
  dispatch_id: string; draft_id: string; source: string; project_no: string; vessel: string;
  client: string; client_address: string; client_email: string; documents: Doc[];
  sent_at: string | null; email_provider_id: string; confirmed_by: string; confirmed_at: string | null;
  completed_by: string; completed_at: string | null;
};
const isoOrNull = (v: unknown) => { const s = cleanText(v, 40); return s && !isNaN(Date.parse(s)) ? s : null; };
export function validate(body: unknown): { ok: true; job: Job } | { ok: false; error: string } {

  const dispatch_id = cleanText(b.dispatch_id, 40), draft_id = cleanText(b.draft_id, 40);
  if (!UUID.test(dispatch_id)) return { ok: false, error: "dispatch_id must be a UUID" };
  if (!UUID.test(draft_id)) return { ok: false, error: "draft_id must be a UUID" };
  const client = cleanText(b.client, 200);
  if (!client) return { ok: false, error: "client is required" };
  if (!Array.isArray(b.documents) || !b.documents.length) return { ok: false, error: "documents must be a non-empty list" };

    if (!title) return { ok: false, error: "every document needs a title" };

      if (!Number.isInteger(Number(o.pages)) || Number(o.pages) < 0) return { ok: false, error: "pages must be an integer" };
      pages = Number(o.pages);
    }
    documents.push({ title, pages });
  }
  return { ok: true, job: {
    dispatch_id: dispatch_id.toLowerCase(), draft_id: draft_id.toLowerCase(),
    source: cleanText(b.source, 40) || "drydocking", project_no: cleanText(b.project_no, 60),
    vessel: cleanText(b.vessel, 120), client, client_address: cleanText(b.client_address, 300),
    client_email: cleanText(b.client_email, 254), documents,
    sent_at: isoOrNull(b.sent_at), email_provider_id: cleanText(b.email_provider_id, 120),
    confirmed_by: cleanText(b.confirmed_by, 120), confirmed_at: isoOrNull(b.confirmed_at),
    completed_by: cleanText(b.completed_by, 120), completed_at: isoOrNull(b.completed_at),
  } };
}
Deno.serve(async (req: Request): Promise<Response> => {
  if (req.method !== "POST") return json({ ok: false, error: "Use POST" }, 405);
  const SECRET = Deno.env.get("DRYDOCK_INGRESS_SECRET");
  const SUPABASE_URL = Deno.env.get("SUPABASE_URL");
  const SERVICE_KEY = Deno.env.get("SUPABASE_SERVICE_ROLE_KEY");
  // fail closed: a missing secret means unusable, never wide open

  if (!secretOk(req.headers.get("x-drydock-secret") || "", SECRET)) return json({ ok: false, error: "forbidden" }, 403);
  let body: unknown;
  try { body = await req.json(); } catch { return json({ ok: false, error: "Body must be JSON" }, 400); }
  const v = validate(body);
  if (!v.ok) return json({ ok: false, error: v.error }, 400);
  const r = await fetch(`${SUPABASE_URL}/rest/v1/rpc/receive_drydock_job`, {
    method: "POST",
    headers: { apikey: SERVICE_KEY, Authorization: `Bearer ${SERVICE_KEY}`, "Content-Type": "application/json" },
    body: JSON.stringify({ p: v.job }),
  });
  const text = await r.text();
  let out: any = null;
  try { out = text ? JSON.parse(text) : null; } catch { /* keep text */ }
  if (!r.ok) return json({ ok: false, error: `receive_drydock_job ${r.status}: ${String((out && out.message) || text).slice(0, 300)}` }, 500);
  if (!out || out.ok !== true) return json({ ok: false, error: (out && out.reason) || "refused" }, 400);
  return json({ ok: true, created: !!out.created, group_id: out.group_id, code: out.code || null, unpriced: out.unpriced || [] }, 200);
});
```

```markdown
### Drydocking ingress — jobs arrive, they are not typed

The drydocking app (Supabase project cqwatccjnzuqjwqmorps plus a Cloud Run
service) POSTs one job to `receive-drydock-job` after it has emailed the
documents. The function checks `x-drydock-secret` against
`DRYDOCK_INGRESS_SECRET` (constant-time, fail closed), validates, and calls
`receive_drydock_job(jsonb)` with the service key. That RPC, in one
transaction, inserts the receipt (`on conflict (dispatch_id) do nothing` — a
retry gets `created:false` and the existing group), fills the client without
overwriting, mints `RSR-DC-MMYYYY-###` by the same max-scan as `nextCode`,
prices each document from the DC catalogue (title match, else the row named
`Drydocking document`, else 0 and recorded in `unpriced`), and inserts one
DRAFT line per document. `drawing_no` stays null; the project number is in
`remarks`. The card shows a `From drydocking` badge from `receiptMap`, which
must never reach the statement (printclean asserts it).

`verify_jwt = false` for this function in `supabase/config.toml` — the caller
holds a secret, not a session. Forgetting it makes every drydocking send sit
at `emailed_billing_pending` over there with "billing ingress returned 401".
```
